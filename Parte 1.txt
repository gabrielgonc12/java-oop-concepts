1. FUNDAMENTOS DE JAVA E COMPILAÇÃO

Q1. Ela está parcialmente certa. O .java não é interpretado direto: primeiro o 
javac compila pra bytecode (.class), e só depois a JVM executa esse bytecode. 
A JVM até interpreta no começo, mas usa o JIT pra compilar os trechos mais 
usados em código de máquina nativo. Ou seja, tem compilação em duas etapas, 
não é "linha a linha" como ela pensa. Por conta desses motivos é um processo 
rápido de dinâmico.

Q2. O erro é de conversão de tipo (sintaxe/tipagem estrita). A
multiplicação de um int por um double resulta em um double, e o
Java não permite guardar um double dentro de uma variável int sem
cast (pois há perda de precisão).

Linha corrigida:
double total = quantidade * preco;

Q18. Isso acontece porque, ao usar remove(i) em um loop crescente (ou
for-each), os índices dos elementos subsequentes da lista são
rebaixados imediatamente, fazendo o índice do loop pular o
próximo elemento.

Solução correta: usar o método remove() através de um Iterator,
ou fazer o for tradicional de trás para frente (decrescente).
